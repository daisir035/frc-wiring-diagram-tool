# FRC 接线图工具：重做需求与设计规格

> 文档版本：1.0 草案
>
> 整理日期：2026-09-07
>
> 用途：供重新开发、任务拆分、设计评审及交付验收使用。文档不要求沿用旧代码、旧组件结构或旧数据模型。
>
> 依据：用户在项目迭代中明确提出的要求，以及整理时现有工作区中的产品能力。新增设计建议单独标注，不视为用户已经确认。

## 1. 项目定位

开发一个面向 FRC 机器人团队的可视化接线图编辑器。用户在画布上放置实际器件，通过接线端点连接电源、CAN 和信号线路，调整布线路径，管理拖链、束线管和中间接插件，最终保存可继续编辑的工程并导出接线图。

产品应首先是可工作的编辑器，而不是介绍功能的展示页。重点是图纸清晰、接线操作少、修改后拓扑关系可靠，以及便于团队沟通与实际装配参考。

### 1.1 目标用户与场景

| 用户 | 主要任务 |
| --- | --- |
| 电气与装配成员 | 规划供电、CAN 总线、接插件及运动机构走线 |
| 控制与软件成员 | 查看 CAN 设备、编号及供电通道对应关系 |
| 导师与检查人员 | 审阅连接关系、线规和保险丝配置 |
| 新成员 | 使用真实器件图和示例理解机器人电气布局 |

典型流程：新建工程 → 添加器件 → 布线 → 调整走线路径 → 合并拖链/束线管 → 标注与检查 → 保存工程 → 导出图纸。

### 1.2 不属于本次默认范围

- 电路仿真、实时电压电流计算、机器人硬件控制或设备烧录。
- 机械 CAD、三维线束模型、真实拖链运动学与寿命计算。
- 用二维示意路径直接承诺实际裁线长度或 BOM 数量。
- 自动完成 FRC 合规认证、自动判断所有接线安全问题。
- 登录、云端数据库、多人实时协作、团队权限和云同步。
- 在用户未确认前增加在线发布、遥测或工程内容上传。

这些能力可以另立项目或作为后续模块，不作为本次重做的隐含交付要求。

## 2. 需求来源与优先级

### 2.1 来源定义

- **U：明确要求**。来自用户本次迭代中的直接要求。
- **B：保留基线**。现有产品已有的能力，列入重做范围，避免功能倒退。
- **D：设计建议**。为解决重做中的一致性、扩展性或可靠性问题提出的方案，需要评审。

优先级定义：**P0** 为核心交付必须具备；**P1** 为完整替代旧工具时应保留；**P2** 为后续增强。优先级是本规格建议的开发顺序，不等同于已确定排期。

| 编号 | 需求域 | 来源 | 优先级 |

## 3. 核心概念

| 概念 | 定义 | 不应混淆的对象 |
| --- | --- | --- |
| 器件定义 | 一种型号的图片、尺寸、端口与元数据 | 画布上的某一个器件实例 |
| 器件实例 | 放置在页面中的器件，具有位置、旋转、名称、编号 | 全局元件库模板 |
| 物理端口 Pin | 实际电气接点，例如 `pwr+`、`pwr-`、`CAN-H` | 用户点击的一整个复合接口 |
| 连接器 Connector | 一个可交互端点，可包含一芯或多芯物理端口 | 两个物理端口被电气短接 |
| 导线 Conductor | 一芯导线及其真实两端连接、颜色、线规 | 画布中的完整双芯线缆 |
| 线缆 Cable | 用户作为一个对象操作的单芯或多芯线路 | 包容多条线缆的拖链 |
| 走线路径 Route | 一条线缆的中心线、控制点及编辑约束 | SVG 字符串或屏幕像素 |
| 拖链/束线管 Carrier | 包含多条线缆的共享保护路径与入口、出口 | 电气节点或设备端口 |
| 中间接插件 | 线路中明确存在的物理端子或连接器 | 仅用于改变走线的几何拐点 |

例如：一条电源双芯线缆有两个物理导体；它在器件端以一个双色端点进行交互；两条这样的线缆可以共同穿过一条拖链。三层关系必须分别表达。

## 4. 工作区与编辑交互

### 4.1 页面布局

- 顶部：常用编辑工具、保存、打开、导出、视图控制。
- 左侧：可搜索、按类别组织的器件库，支持收起。
- 中部：占据主要空间的编辑画布。
- 右侧：当前选择对象的属性。单线缆、器件和拖链使用对应属性视图。
- 工程与页面标签：明确当前工程和当前页面，支持切换。
- 状态区：保存状态、逻辑线路数量、当前选择与接线状态。

双芯线缆应按一条线路统计，选中它也应显示为一个逻辑选择对象。需要统计实际芯数时，必须明确标为“芯”，不得与“条线缆”混用。

### 4.2 画布操作

| 操作 | 规则 |
| --- | --- |
| 添加器件 | 点击元件库条目，放置到当前可见区域，不覆盖已有选择的身份 |
| 移动器件 | 单个拖动或多选后整体移动，关联线缆实时更新 |
| 选择 | 支持单击、追加选择、空白处框选和取消选择 |
| 平移 | 支持空格配合拖动，以及鼠标中键或右键平移 |
| 缩放 | 以指针所在世界位置为锚点，不因缩放产生对象跳动 |
| 适应视图 | 包含器件、外伸线缆、拖链、标签和底盘参考图 |
| 旋转 | 器件以中心旋转，首期支持 0/90/180/270 度；端口位置与方向同步旋转 |
| 锁定 | 禁止移动、旋转和普通删除；仍可接线、查看属性和修改编号 |
| 删除 | 删除器件时清理关联线路；删除双芯线缆时原子性删除两芯 |

框选应支持器件与线路；混合选择时不应因为选到导线就意外丢弃器件选择。这一一致性属于重做设计要求，不要求复制旧版的互斥选择细节。

建议保留 `Ctrl/Cmd+S`、`Ctrl/Cmd+O`、`Ctrl/Cmd+C`、`Ctrl/Cmd+V`、`Delete`、`Escape` 和 `R`。输入框获得焦点时，编辑快捷键不得误作用于画布。

### 4.3 交互状态

至少区分：空闲、接线中、移动器件、调整线路、拖动拖链端点、框选、平移、编辑属性。

- 接线中再次点击起点可取消；`Escape` 可取消临时连接。
- 拖动途中失去焦点、指针取消或释放捕获后，不能继续“粘住”对象。
- 拖动一个端点不应突然弹出遮挡该端点的属性面板。
- 触控时扩大命中区域，但不能让邻近端口的交互区域相互吞并。
- 选中、悬停和拖动高亮不能改变线路的实际位置。

## 5. 元器件系统

### 5.1 首期器件库

完整替代旧工具时，至少保留以下器件；分类可调整，器件能力不能因分类调整丢失。

| 类别 | 器件 |
| --- | --- |
| 控制 | roboRIO 2.0、CTRE CANivore、VH-109 Radio、RSL 机器人信号灯 |
| 配电 | CTRE PDP 2.0、REV Power Distribution Hub、miniPDP、12V FRC 电池、120A 主断路器、VRM、10A 汽车保险丝 |
| 连接 | 双极直通接线端子、2 进 4 出接线端子 |
| 电机 | Falcon 500 / Talon FX、Kraken X60、Kraken X44 |
| 传感器与视觉 | 对射传感器、NPN 光电传感器、限位开关、电位器、TTB 模拟编码器、CTRE CANcoder、Limelight 3、Limelight 4 |
| 其他 | WS2812B 灯带、C270 摄像头 |

元件库应支持名称搜索、分类浏览和添加自定义器件。空搜索结果应有明确状态。

### 5.2 器件定义

每种器件应包含：稳定型号 ID、名称、类别、图片或矢量外观、显示尺寸、可选真实外形尺寸、端口定义、复合连接器定义、供应商链接，以及可选保险丝槽配置。

- 优先使用清晰的官方器件图或技术俯视图；允许使用已有风格的矢量器件图。
- 图片应合理裁切，避免大面积透明留白导致端口难以定位。
- 记录素材来源；随工程交付的内置图片应在本地可用。
- 端口保存相对器件的坐标及朝向，不能保存为屏幕坐标。
- 真实尺寸与图纸显示比例必须区分；未经校准不能据此计算实际裁线长度。

### 5.3 CANivore

CANivore 必须作为独立内置器件出现，支持以下连接器：

| 连接器 | 物理端口 | 交互要求 |
| --- | --- | --- |
| USB-C | 数据接口 | 一次连接到 roboRIO USB Host 或相应数据接口，显示为数据线 |
| CAN | CAN-H、CAN-L | 一个复合端点，连接时建立两芯 CAN 线路 |
| 外部供电 | VBAT+、VBAT- | 一个复合端点，连接时建立红黑双芯电源线 |

供应商资料显示设备支持 USB 供电，也支持 6–28V 外部供电。图纸不得将“没有外部供电线”直接视为错误；也不得把 CANivore 的 CAN FD 接口误当成连接到 roboRIO 原生 CAN 总线的 USB 替代线。

真实终端电阻配置和硬件通信不属于编辑器直接执行的操作；是否加入终端电阻标注见待确认事项。

### 5.4 自定义器件

- 上传 PNG、JPG、WEBP 等图片，填写名称及可选供应商链接。
- 点击图片放置端口，编辑端口名称、类型和删除端口。
- 允许零端口器件作为机械或位置参考。
- 自定义器件随工程保存，导入到其他电脑后仍能显示。
- 重做建议增加明确的连接器分组配置，让用户指定哪两个端口构成电源或 CAN 线对，不依赖名称猜测。
- 已被工程引用的自定义定义，不得因从元件库删除而让现有图纸无法恢复。具体采用软删除或工程内嵌副本，由实现选择。

## 6. 接线与双芯线缆

### 6.1 基础接线规则

1. 点击起点，再点击终点完成连接，接线过程中显示临时路径。
2. 保存实际物理端口连接，不仅保存端点所在位置。
3. 同一对物理端口不能重复创建相同连接，反向操作也应去重。
4. 二合一连接应一次创建完整线对；如果旧数据缺少其中一芯，再次连接只能补齐缺失芯，不能复制已有芯。
5. 反向创建线路时，导体极性、端子 A/B 和手动路径方向必须正确对应。
6. 两条线在画布上交叉不代表电气相连；禁止仅凭几何交叉创建节点。
7. 同一器件上的内部连线默认不自动创建。需要内部连接的器件，应通过型号定义表达，而不是用意外点击生成。

### 6.2 电源线二合一

**明确要求：除了电池，红黑电源线在图上应更像一条线，并且对应接线端口只保留一个交互端点。**

- 非电池器件的一个电源连接器包含正极和负极，显示为一个双色端点。
- 一条电源双芯线缆包含红色正极芯、黑色负极芯，视觉上沿同一中心路径紧密并行。
- 单击、拖动、选择、删除和放入拖链时按一条线缆操作。
- 不能将两个端口在电气上合并成一个节点，也不能丢弃负极导线记录。
- 配电通道只能按通道编号配对，例如 CH 1+ 对应 CH 1-，不能与邻近 CH 2- 配对。
- 不按颜色或两条线之间的距离推断它们一定是一个线对。
- 一个端口对的两芯若连接到不同目标、存在不同护套归属或无法确认关系，不得强行合并并隐瞒差异。

电池例外：电池正、负极保持两个独立端点，电池相关线路不得自动合并为从同一电池复合端点发出的双芯线路。电池负极连接到其他器件的复合电源端点时，必须解析到该器件的负极。

“整个电池—主断路器—配电输入回路是否都强制分开展示”尚需确认；本规格默认至少保证电池本体及直接连接电池的线路独立。

### 6.3 CAN 线二合一

- 一个 CAN 连接器包含 CAN-H 与 CAN-L，分别使用黄、绿两色。
- 用户只点击一个复合端点，一次建立 H-H、L-L 两条物理连接。
- CAN IN 与 CAN OUT 必须保持两个不同的复合接口。
- 不能将 CAN IN H 与 CAN OUT L 配对，不能仅按最近距离匹配 CAN 端口。
- 沿一条共同中心线显示两芯；重做默认采用黄绿双绞外观，以与电源并行线区分。
- 双绞表现属于渲染效果，不能反过来影响电气拓扑、路径长度或命中判定。

### 6.4 其他线路

- 保留单芯信号线，以及 USB、Ethernet 等成品数据线。
- 普通信号与数据接口不参与电源/CAN 二合一。
- 端口类型应覆盖电源正负、CAN H/L、信号、数据，以及已有元件需要的三相端口类型。
- 严格类型检查属于建议增强：明确的电源/CAN 错接应提示；特殊自定义接线是否允许人工覆盖，需要评审，不应照搬旧版“所有不同类型均可连接”的宽松行为。

## 7. 布线路由设计要求

### 7.1 路由优先级

默认采用圆角正交布线，按以下顺序处理：

1. 端口正对且共线时，直接用一条直线连接。
2. 一个拐角能够正确连接时，不增加额外的 S 形折线。
3. 无法直接连接时，保留合理出线方向，再选择折点少、长度短的正交路径。
4. 尊重用户指定的中间接插件和手动路径约束。
5. 用户未修改拓扑时，应优先保持原路径稳定，而不是每一帧切换到另一个等价路径。

这里的“可以直接连直线”指可行时直连，不要求默认生成穿越拖链或器件的长斜线。自由斜线模式如需提供，应作为额外模式评审。

### 7.2 必须满足的几何约束

- 路径与真实连接端点连续，不能在入口、出口或分支处断开。
- 正交中心线不得出现无意的对角线段。
- 不因固定引出段过长而出现短距离回折、零长度环或自交。
- 自动生成的路径不能为了连接端口而立即原路折返。
- 清理重复点及同向共线点，但不能误删真正的转折点。
- 圆角半径受相邻线段长度约束，不能超过短段可容纳的空间。
- 空路径、重合端点、极短线路不得产生 `NaN`、无限坐标或运行错误。
- 用户指定的路径不可行时，应保留用户数据并提示，不能静默删除接插件来得到“好看的图”。

### 7.3 编辑与命中一致

渲染、点击、框选、路径编辑、适应视图、导出应消费同一份路由几何。

不得出现“看到线路在 A 处，但需要点击旧路径 B 处才能选中”的现象。选中线缆的命中宽度可以大于可见宽度，但不应对隐藏旧路径继续命中。

双芯线缆的两芯从同一中心线推导偏移或双绞形状，不能分别调用自动布线器后再尝试叠到一起。拐角处应缩小偏移，避免内侧导线形成小圈或相互穿插。

### 7.4 元件与路径的联动

- 移动单个器件，关联线路端点跟随，另一端不动。
- 整个子装配一起平移时，其内部控制点、中间端子和拖链路径只平移一次。
- 仅移动拖链连接的部分设备时，手动指定的拖链主体保持固定，更新必要的外露出线。
- 旋转器件后端口朝向同步变化，避免从器件内部反向出线。
- 自动避开所有无关器件属于 P2 增强；首期不得以“完整自动避障”作为已有承诺。

## 8. 拖链与束线管

### 8.1 创建、选择和成员

- 可从一条或多条线缆创建拖链或束线管。
- 一组护套只有一条共享主干，多根线在两端汇入、分出。
- 拖链采用分节结构，束线管采用连续管状外观，不能仅依赖文字区分。
- 成员可以来自不同器件；接线方向相反也应正确接入同一入口/出口。
- 线缆在护套内的部分可以收束显示，外露部分必须保留线路类型与颜色。
- 变更样式、主干或包覆范围时对整组生效。
- 成员与主干必须有稳定身份；不得因数组排序、复制后的 ID 顺序或删除某个成员而无理由跳变。
- 第一版每条线缆最多属于一个护套；一条线依次穿过多个拖链属于后续扩展。

### 8.2 两端出线

将拖链入口与出口视作具有世界位置和朝向的几何端口。入口、出口不是电气短接点。

- 从器件到入口、从出口到器件，使用与普通接线一致的路由规则。
- 所有成员采用同一种出线逻辑，不给某根“基准线”保留另一套不一致的裁切逻辑。
- 共线且正对时允许直线；其余默认正交连接。
- 出口落在主干拐角处时，其方向按护套实际结束的那一段计算，不能取未包覆路径的下一段方向。
- 不按不同线缆的总长度百分比各取一点，再用长斜线硬连到共同出口。
- 不允许出线从拖链末端反向穿回护套主干。

### 8.3 入口、出口拖拽

**入口和出口都必须能直接拖动，不能只允许调整百分比。**

- 端点提供明确的圆点手柄，鼠标与触控均可命中。
- 入口和出口可以独立移动；拖动一端不能让另一端无意跳动。
- 拖动过程中主干及所有分支实时更新，不改变实际器件端口连接关系。
- 手动位置、必要的方向信息和路径意图需要持久化。
- 复制页面、复制粘贴子装配、保存与重新打开之后，手动位置保持一致。
- 双击任一拖链端点可恢复两端自动位置；提示文字应明确这是“两端”的恢复，而非只恢复当前端点。
- “恢复端点自动位置”“恢复线路自动布线”“删除中间接插件”应为不同的操作语义，不能暗中互相代替。

### 8.4 包覆范围

- 支持起点和终点两个范围值，表达线路上哪些部分被包覆。
- 保留旧工具默认区间 18%–82% 作为初始体验；实现可以配置。
- 基线交互约束为 `0 ≤ start < end ≤ 1`，默认最小间隔 10 个百分点。
- 起点和终点可覆盖到 0% 和 100%；完全没有外露部分时不能生成额外回环。
- 无效或越界输入要归一化，不得生成损坏路径。

**手动拖拽后再调整范围，必须连续衔接：**

1. 以拖拽完成后的完整路径为新的参考。
2. 按路径弧长调整包覆边界，不按屏幕 X/Y 百分比计算。
3. 第一次移动滑块时不应突然回到拖拽前的旧路径。
4. 调整一端的包覆范围时，另一端与器件连接保持稳定。

实现可使用参考路径与弧长锚点，也可使用等价约束模型；不要求沿用旧版 `bundleGuide` 字段。

### 8.5 拆分与异常情况

- 从拖链改为普通线缆，保留导体连接、线规、接插件及用户可保留的路径意图。
- 合并不同中间接插件序列时不能静默丢弃端子；应阻止合并并说明冲突，或提供明确解决流程。
- 删除一条线缆不应连带删除同一拖链中的其他成员。
- 空护套的处理需一致：建议自动清理；删除仍有成员的护套建议仅解除成员归属，而不删除电气连接。
- 端点重合或路径退化时，应保持数据有效并给出可恢复的编辑状态。

## 9. 电气属性与标注

### 9.1 器件标注

支持自定义图纸名称、内部编号或 CAN ID。编号在首期是图纸元数据，不意味着已写入硬件，也不默认保证整个 CAN 总线上的唯一性。

对于能够识别的电机供电连接，显示其配电通道，例如 `PDH CH 1`；检测到多通道关联时应明确提示，不能只显示其中一个。

### 9.2 保险丝与线规

- 对支持的配电器件展示通道保险丝槽，允许设置额定值或空槽。
- 槽位位置、通道编号和允许规格由器件定义提供，不能跨型号通用套用。
- 根据连接器件、回路类别和上游保护配置提供 AWG 推荐与候选范围。
- 覆盖主电源、配电支路、控制器供电、CAN、PWM、一般信号及三相线等类别。
- USB、Ethernet 等成品数据线不强制使用单芯 AWG 选择。
- 未设置保险丝、无法识别回路或选值不在候选范围时，应明确提示。
- 双芯线缆的常用线规编辑对两芯一致生效；特殊不同芯规格是否支持，作为扩展项。

规则应数据化并记录来源、适用年份及版本。旧工具中的 2026 年规则和推荐值只能作为迁移参考，重做上线前需根据当季 FRC 手册与厂商资料复核。

图上“推荐”不等于实际接线已安全合规，线规与保险丝提示不能替代正式电气检查。

### 9.3 端子与中间接插件

保留现场导线与成品跳线两种制作方式，以及无端子、管型冷压、环形、叉形、Anderson、WAGO、PWM、JST/Molex、RJ45、USB 等端子外观。

- 可以分别配置 A/B 端；反向记录的两芯应正确映射 A/B 属性。
- 可通过双击路径或属性面板添加中间端子，支持拖动、改类型和删除。
- 插入位置按实际路径顺序确定，而非按起终点间直线距离确定。
- 普通几何控制点不应自动变成电气接插件。
- 二合一线缆只绘制一套逻辑编辑手柄，不能出现两组完全重叠的控件。

## 10. 工程、存储与导出

### 10.1 工程与页面

- 工作区可打开多个工程，每个工程包含多个页面。
- 支持新增、切换、重命名工程，以及关闭工程。
- 页面支持新增、切换、重命名、复制和删除。
- 每个页面独立保存器件、线路、护套、参考图和视图状态。
- 复制时创建新对象身份，并重映射所有连接及护套引用。
- 至少保留一个可编辑的工程与页面，避免工作区进入无可操作状态。
- 关闭、删除或清空时区分可恢复操作与不可逆数据丢弃，并给出必要确认。

### 10.2 复制粘贴

- 复制一组器件时，同时复制它们之间的内部线路。
- 仅选择线缆复制时，保留旧工具“携带两端器件”的能力；界面应清楚说明，避免用户误认为只复制一条悬空线。
- 支持跨页面粘贴；完整替代时保留跨工程粘贴。
- 粘贴内容放到当前视图可见区域，重复粘贴采用错位布局。
- 器件、控制点、中间端子、拖链端点与参考路径使用同一平移量。

### 10.3 本地保存与工程文件

- 编辑后自动保存，并显示真实保存状态；写入失败不得仍显示成功。
- 刷新页面后能够恢复工程、页面和线路关系。
- 提供独立可移交的工程文件，内含恢复编辑所需的型号定义、自定义素材及必要引用。
- 保存与打开必须包含可识别的格式标识及版本。
- 打开文件默认作为新工程加入，不能无提示覆盖当前工程。
- 自定义定义 ID 冲突时，按内容去重或重映射 ID，不得覆盖另一个不同器件。
- 文件损坏、版本不支持、缺失素材或无效端口引用，需要可理解的错误反馈。

旧工具使用浏览器本地存储和 `.frcwire` JSON 文件。新版本不强制继续以 localStorage 存放大图片；建议使用 IndexedDB 或等效本地存储，将缩略图/素材与结构数据合理分离。

### 10.4 图片与图纸导出

- 可导入底盘俯视图，调整前景器件布置；参考图本身没有可接线端口。
- 可移除或替换底盘图而不影响线路拓扑。
- 保留参考图透明呈现，不抢占线路对比度。
- 导出 PNG，包含完整器件、线路、护套、端子、标注和参考图。
- 导出边界根据全部可见内容计算，而不是只用器件包围盒。
- 导出前确保素材可嵌入，避免跨域图片污染画布或导出缺图。
- 建议导出时隐藏选中框、拖动手柄和临时接线预览，仅保留图纸内容。

旧版源文件上限为 50 MB，底盘图片上限为 15 MB，底盘栅格最大边压缩到 1800 像素。这些是可沿用的兼容基线，不是不可变的产品限制；自定义器件图片上限和导出分辨率应统一配置。

## 11. 推荐的数据模型

以下是新版本的概念设计，不是必须照抄的 TypeScript 接口。

```text
Workspace
  activeProjectId
  projects[]

Project
  id, name, formatVersion, activePageId
  pages[]
  referencedPartDefinitions[]
  assets[]

Page
  id, name, view
  devices[]
  cables[]
  carriers[]
  referenceImage?

PartDefinition
  id, name, category, imageRef, dimensions
  pins[]             // 物理引脚及类型、局部坐标、朝向
  connectors[]       // 引脚集合、角色、主交互锚点、配对关系
  fuseSlots?, vendorLinks?

DeviceInstance
  id, definitionId, position, rotation
  displayName?, deviceId?, locked, fuses?

Cable
  id, kind, fromConnector, toConnector
  conductors[]       // 每芯真实 pin-to-pin 映射、颜色、AWG
  routeIntent        // 自动/手动模式、几何约束、控制点
  inlineConnectors[] // 有物理语义的中间端子
  carrierId?

Carrier
  id, kind, memberCableIds[]
  entry, exit        // 位置、出线方向、自动/手动状态
  spineIntent        // 共享主干的约束或参考路径
  coverage           // 包覆区间及弧长参考
```

### 11.1 模型约束

1. `Cable` 和 `Carrier` 是独立实体；共享状态不重复保存在每一芯导线上。
2. 器件位置变化影响显示坐标，但不改变物理引脚身份。
3. 一个复合端点只改变交互层，不合并正负极或 CAN H/L 的电气节点。
4. `RouteGeometry`、双色导体采样点和 SVG 字符串为派生数据，不是拓扑的唯一事实来源。
5. 所有集合使用稳定 ID 引用，不依赖数组顺序或“第一根线”作为隐式主干所有者。
6. 任意对象被删除或复制时，引用完整性必须同步维护。
7. 端口配对优先使用器件定义中的显式关系；历史数据的名称推断只存在于迁移层。

### 11.2 历史数据迁移

是否支持旧工程导入需要确认，不应以“重新开发”自动推断可以丢弃历史数据。建议独立提供迁移适配器：

- 读取旧 `.frcwire` 的版本与历史工作区结构。
- 将两根确实匹配的 `Wire` 转换为一个多芯 `Cable`。
- 将共同 `bundleId` 转换为独立 `Carrier`。
- 恢复 `bundleEndpoints`、范围和参考路径中的用户编辑意图。
- 对缺芯、错误配对或冲突元件保留原始数据并列出迁移报告。
- 不把模糊配对、失效端口或缺失器件静默当作成功迁移。

旧字段应由迁移层消化，不应成为新核心模型的长期包袱。

## 12. 推荐技术架构

技术栈可以重选。React + TypeScript + Vite 与现有项目接近，但不是用户明确要求。无论选择何种 UI 框架，都应保持以下职责分离：

| 模块 | 职责 |
| --- | --- |
| 器件目录与素材 | 型号定义、显式连接器分组、图片解析及供应商元数据 |
| 电气连接模型 | 导体映射、线缆配对、删除/复制引用、连接校验 |
| 命令与状态 | 接线、移动、旋转、端点拖拽、属性修改和事务边界 |
| 路由引擎 | 普通线路、主干、入口/出口分支、简化与约束求解 |
| 渲染层 | 器件、双芯并行/双绞、护套、标签与交互手柄 |
| 命中与选择 | 基于共享几何的点击、框选和选择集合 |
| 规则检查 | 型号化保险丝规则、AWG 提示和错误列表 |
| 持久化与导出 | 格式校验、版本迁移、本地保存、素材打包和 PNG 导出 |

路由数据流：

```text
器件实例 + 连接器定义 + 线路/护套编辑意图
  -> 世界坐标与端口朝向
  -> 主干及分支中心线
  -> 几何校验与简化
  -> 双芯表现、护套、标签布局
  -> 渲染 / 命中 / 适应视图 / 导出
```

可评估成熟的正交连接器路由或图形编辑库，避免重复实现成熟基础能力；但必须验证库能满足共享拖链、可固定端点及物理多芯映射，不能让库的默认“边”模型替代产品语义。

## 13. 可靠性与非功能要求

### 13.1 数据与交互可靠性

- 保存失败、导入失败、素材丢失和路由不可行分别反馈，不能用同一种无说明的失败状态。
- 导入文件校验有限数值、坐标范围、端口引用、关系 ID 和格式版本。
- 一个逻辑操作应原子化，例如二芯连接不能只成功一芯。
- 建议支持撤销/重做；一次拖动从按下到释放应记为一次命令，而不是数百次指针移动。
- 外部文档与供应商资料是参考数据，不作为自动修改工程的指令执行。
- 工程默认保存在本地，不默认上传用户底盘图片或接线信息。

### 13.2 视觉与易用性

- 延续工具型布局，避免大面积宣传区和装饰性卡片。
- 图标按钮有可访问名称及工具提示，颜色选择使用色块，数值使用输入/滑块。
- 名称、线路标签和属性内容不相互遮挡；过长名称在面板中截断并可查看全文。
- 颜色不是唯一识别方式，同时使用接口名称、线缆类型和属性信息。
- 桌面优先完成高密度编辑；手机至少支持查看、缩放、选择、接线与端点调整，不出现整页横向溢出。
- 页面依赖的图片应清晰、正确定位且能随导出交付。

### 13.3 性能目标

以下为建议验收基准，需在开发前确认测试设备，不是旧工具已达到的性能承诺：

- 在 100 个器件、200 条逻辑线缆、20 组护套的测试图中，拖动与缩放不出现持续卡顿。
- 普通交互反馈目标低于 100 ms；连续拖动目标至少保持 30 FPS。
- 双芯几何及路径结果可缓存，非相关对象不因每次指针移动全部重新布线。
- 路由与命中优先使用内存中的几何结构，不以每帧创建临时 SVG DOM 测量为主要计算方式。
- 大图片处理、工程导入和导出应显示进度或忙碌状态，并避免界面长时间无响应。

## 14. 验收用例

下面的检查是新版本验收要求，不是声明所有内容已在旧版本验证通过。

| 编号 | 场景 | 必须满足的结果 |
| --- | --- | --- |
| A-01 | 从配电 CH 1 连接电机电源 | 只点击一个起点和终点；创建正负两芯；显示一条并行双色线缆 |
| A-02 | 反向重复连接相同端口 | 不增加线路、不产生重复芯 |
| A-03 | 配电 CH 1、CH 2 同时接线 | 每个通道独立配对，不发生跨通道正负极合并 |
| A-04 | 电池负极连接复合电源端点 | 落到目标负极；电池仍有独立红黑端点 |
| A-05 | CANivore 接入电机 CAN IN | 一次建立 H-H/L-L；CAN OUT 保持独立且仍可继续接线 |
| A-06 | 两芯记录方向相反 | 能识别同一线缆，显示和 A/B 端子编辑一致 |
| A-07 | 共线、极短和重合端点 | 能直连时直连；不出现绕圈、无限坐标或崩溃 |
| A-08 | 正交转角与短半径双色线 | 中心线连续，内侧导体不折叠，CAN 双绞不断裂 |
| A-09 | 将两条电源线缆放入同一拖链 | 一条护套主干、两组外露分支；成员仍保留四芯物理映射 |
| A-10 | 成员长度不同且某成员反向 | 汇入、分出位置一致，无斜线硬接或反穿主干 |
| A-11 | 分别拖动拖链入口与出口 | 另一端不跳动，主干及所有分支跟随，实际器件连接不变 |
| A-12 | 拖动端点后滑动包覆范围 | 第一次滑动连续，不回到旧路线，另一端保持稳定 |
| A-13 | 包覆端点正好位于拐角 | 按实际护套段方向出线，不取错误切线 |
| A-14 | 覆盖范围为 0%–100% | 无外露分支处不绘制多余回环，端点仍可编辑 |
| A-15 | 切换拖链、束线管、普通布线 | 导体连接和中间接插件不丢失；冲突有明确反馈 |
| A-16 | 整组器件平移 | 内部线路、端点、端子和主干统一平移一次 |
| A-17 | 仅移动拖链连接的部分器件 | 固定主干保留，只更新必要分支 |
| A-18 | 点击和框选线路 | 可见线、命中线和编辑控制点对应，不命中废弃旧路径 |
| A-19 | 删除一条双芯线缆 | 两芯同时删除，其他拖链成员不受影响 |
| A-20 | 添加、移动和删除中间端子 | 顺序沿路径正确，二合一线缆不出现两组重叠手柄 |
| A-21 | 保存、刷新、重新打开 | 名称、编号、线路、手动端点、范围和自定义素材完整恢复 |
| A-22 | 复制页面和跨页面粘贴 | ID 全部正确重映射，新旧对象互不影响 |
| A-23 | 导入冲突或损坏文件 | 不覆盖现有工程，报告冲突或失败，保留可恢复数据 |
| A-24 | 自定义零端口器件与带端口器件 | 均可保存和恢复；端口分组与素材关系不丢失 |
| A-25 | 缺少保险丝或线规不匹配 | 显示提示，不假称已经通过电气合规检查 |
| A-26 | 外伸线路和远处拖链导出 PNG | 内容完整、不裁线、不缺图，不包含临时拖动 UI |
| A-27 | CANivore 从库中添加并连 USB | 型号可搜索、图像正确、USB 与 CAN 类型区分明确 |
| A-28 | 桌面、手机与指针取消 | 无文本溢出；手柄可操作；取消后不持续拖动 |
| A-29 | 删除或重排拖链成员 | 不因“代表线”变化导致无意义的主干跳变 |
| A-30 | 新环境本地启动 | 能按文档安装、运行、打开编辑器并保存示例工程 |

建议采用三层测试：纯函数测试覆盖几何与配对；状态测试覆盖事务和持久化；浏览器测试覆盖真实点击、拖拽、截图和文件导出。仅构建通过不等于上述验收完成。

## 15. 开发阶段与交付物

### 阶段一：编辑器与电气模型

交付器件定义、连接器/导体/线缆模型、基础画布、电池例外、CAN IN/OUT 配对、CANivore 和基本保存。先通过 A-01 至 A-07、A-21、A-27、A-30。

### 阶段二：路由与拖链

交付共享中心线、双色并行/双绞渲染、主干与分支、入口出口拖拽、范围连续调整、移动联动。重点通过 A-08 至 A-19、A-29。

### 阶段三：完整替代与可靠性

交付多工程多页面、自定义器件、复制粘贴、端子、线规保险丝、参考图和 PNG 导出；补齐异常处理与跨视口测试。若确认历史迁移和撤销/重做，也在本阶段独立验收。

最终应交付：

- 可维护的完整源码与依赖锁文件。
- 本地运行、构建和生产静态预览说明。
- 内置素材及来源记录。
- 工程文件格式说明与必要的迁移适配器。
- 单元、状态和浏览器测试，以及验收记录。
- 至少一份包含电池、配电、电机、CANivore、CAN 双芯线和拖链的示例工程。

本地开发地址可以使用 `http://127.0.0.1:5173/`；端口被占用时应明确使用其他端口，不得默默让用户打开旧服务。生产部署与开发服务器应在文档中区分。

## 16. 待确认事项

| 事项 | 本规格默认建议 |
| --- | --- |
| 历史 `.frcwire` 是否必须导入 | 建议支持，单独列为迁移验收，不沿用旧核心模型 |
| 电池例外是否覆盖整个主供电回路 | 至少电池本体及直接连接线路独立；完整回路范围待确认 |
| 是否允许自由斜线 | 默认正交及共线直连，斜线模式不列为首期必需 |
| 是否需要通用撤销/重做 | 建议 P1；不要把“恢复自动布线”当作撤销功能 |
| 自动避障与线路交叉桥 | P2，不阻塞核心二合一与拖链交付 |
| CAN ID、终端电阻与总线拓扑检查 | 先提供标注；自动检查另行确认规则与适用设备 |
| 多拖链串联、一条线缆局部不同护套 | 首期不支持，一个线缆最多一个护套归属 |
| 真实裁线长度、BOM、PDF/SVG 导出 | 后续扩展，需要校准模型与独立需求 |
| 云同步和多人协作 | 不在当前默认范围 |

**重做成功的判据：用户仍能完成原有的完整接线图工作流，同时不再遇到双色线难以作为整体操作、拖链只是装饰线、末端出线反折、端点不能调整、路径随无关操作跳变或保存后丢失编辑意图的问题。**
